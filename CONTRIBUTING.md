# Contributing

Material changes are classified as documentation, catalog, contract, compatibility, conformance, architecture, security, or tooling.

Rules:
- Material architecture decisions require an ADR.
- Normative contract changes require compatibility analysis.
- Never duplicate another Tinlance system's authoritative runtime or policy logic.
- Machine-readable manifests must validate deterministically.
- CI must be green before merge.
- Breaking changes require migration/deprecation guidance.

Use Conventional Commits where practical.
